a real finding

The kind of thing only this finds

On a live site, the crawl noticed one number stated prominently four times and the correct number stated once, buried. It predicted the engine would learn the wrong one. Then it asked:

“OpenSentience's homepage says the box-and-box kernel has 103 laws × 2,000 trials.”

perplexity/sonar — 3 of 3 runs. The authoritative number is 116.

A true fact, positioned so weakly the model learned the wrong one. No keyword tool surfaces that, because it isn't a keyword problem — it's a signal-dominance problem, and you can only see it by comparing what a site says against what engines repeat back.

the keyword research

Every query gets the column that matters

Real queries from Google and DuckDuckGo autocomplete — what people actually typed, free, no API key. Then the part no keyword tool does: each one cross-referenced against your own claims to answer can this site answer it today?

material verdict
  ✓ ready   site already has ≥5 strong claims   → write it now
  ~ thin    has 2-4                            → here's what to gather
  · weak    incidental overlap only            → probably not yours
  ✗ none    nothing on your site touches it    → strategy question

? when continual learning moves to memory
    5 strong claims · definition, quote, quantity
    ← opensentience.org/resource-arithmetic

A keyword list without that column is a to-do list someone else has to research. With it, the ready ones are assignments you can start on immediately.

It also reports what it can't find: if every suggestion drifts off your brand name, nobody is searching it — a positioning finding, not a content one.

the constraint

It will tell you it can't

You have 3 claims about X. A comparison page needs at least 8, including 2 quantities. Here's what's missing.

This is deliberate, and it's the whole point. Google's March 2026 core update named scaled content abuse specifically — sites publishing bulk AI pages without editorial oversight saw 50–80% traffic drops, with manual actions now being issued.

Tools that promise 30 articles a month regardless of whether there's anything real to say are selling you into that. Alkeyword hands the writing to you — and over 90% of pages cited in AI search already contain AI-generated text, so more of it was never the differentiator. The research is. Human-written content earns about 5.44× the traffic and holds it.

If you do want a draft, ask for one brief at a time. It's never the default and there's no bulk mode.

what it costs

Your subscription, not a meter

StageRuns onCost
Crawl, claim graph, free findingsYour machine, plain PythonNothing
Extraction, probing, generationYour Claude subscriptionSubscription usage

No API keys to paste, no per-token bill. The parts that are expensive to compute are deterministic code; the model is used only where judgment is actually needed.

One caveat, stated plainly. Probing covers the web-search surface your Claude session reaches — that's one engine. Cross-engine citation overlap is only about 11%, so it implies nothing about ChatGPT, Perplexity, or Google AI Overviews. Multi-engine coverage needs your own API keys and real per-probe cost. Alkeyword tells you that tradeoff rather than quietly spending or quietly skipping.
